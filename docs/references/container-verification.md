## 真实 API 与媒体结果

使用独立 Compose 项目 `soundpick-mvp-check`。临时覆盖仅将监听端口设为 `127.0.0.1:18000`、结果保留期设为 5 秒，用于实际到期检查；原 `.env` 和 Compose 的默认保留期不变。已有手机入口不使用该测试端口。

| 输入 | MP3 与试听下载 | 声音核对 |
|---|---|---|
| 真正生成的 4 秒双音轨视频，经 TCP 上传 | 82,844 字节，FFprobe 时长 4.104 秒，完整解码时长 4.032 秒；audio/mpeg 附件及 Range 206 正常 | 首、中、尾各取 0.4 秒，以 16 kHz 解码，原视频第一音轨与 MP3 的相关性均高于 0.999999；排除第二音轨干扰 |
| 当前火山版分享文本 `https://v.douyin.com/DUMJbobJ4gY/` | 容器实际执行公网解析、下载和转码，输出 290,942 字节；FFprobe 时长 12.094694 秒，完整解码时长 12.0511875 秒；附件及 Range 206 正常 | 目标视频 7659736603242784995 的已核实原音轨为 12.050998 秒；首、中、尾各取 0.4 秒，相关性分别为 0.999853、0.999975、0.999967 |

MP3 编码填充带来的时长差异符合 [行为规格](../active/0.1.0/audio-extraction/spec.md) 的误差范围，不声称逐点无损一致。容器火山声音与此前已核实来源的原视频比较，未记录本次容器输入文件的 SHA-256；平台来源边界见 [平台解析记录](./platform-parsing.md)。

匿名媒体能力接口返回 401，实际共享口令登录返回 303，认证后媒体工具可用。两项结果到期后的文件请求均返回 404，后台清理实际删除任务目录。验收结束后仅移除本轮新建的测试容器、网络和数据卷，并确认测试项目没有剩余容器或数据卷；本地构建镜像保留。

首次容器核对脚本使用 1 kHz 采样，会滤掉合成样本的 880 Hz 尾段标识；对同一份 MP3 的诊断确认 16 kHz 下声音吻合后，修正测量方法并重新执行全套容器检查。应用和 Docker 配置没有为此改动。检查脚本、短保留期配置、媒体及 JSON 输出已在后续裁剪中清理，本文保留当时的运行环境、结果和验收边界。
