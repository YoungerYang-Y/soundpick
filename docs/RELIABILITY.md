# 可靠性标准

项目尚未定义正式 SLO，也没有生产运行数据；不要把本地检查结果称为线上可用性或性能证明。

## 服务目标

| 服务 | 当前目标 | 验证方式 |
|------|----------|----------|
| Web 页面与登录 | 请求失败时返回明确错误；配置无效时启动失败 | 本地请求与配置校验 |
| 媒体任务 | 单次任务成功交付可播放的完整 MP3，失败时清理临时数据 | 服务层检查、媒体工具和端到端流程 |
| 健康检查 | `GET /healthz` 给出最小存活结果 | HTTP 请求 |

不设定未经测量的延迟、可用性或错误率数字。30 秒不是产品硬指标。

## 任务与资源边界

- 工程默认输入200MiB/1800秒、上传300秒、处理600秒、结果3600秒；可配置，不代表用户产品硬指标或性能承诺。
- 单实例内存任务状态已实施，不跨重启或多实例存续；一个活动任务和最多32个保留任务，同一目录有进程锁。所有终态计入容量和到期回收。
- 成功删输入、失败/取消删全目录；结果到期拒绝新请求，活动下载结束后清理。磁盘清理失败周期重试，下次启动清理专属残留目录；不触及其他用户数据。
- 解析不到确认为原音轨的内容时，应明确失败，不能静默返回不匹配媒体。

## 可观测性

记录任务阶段和错误类别以便排障，不记录共享密码、Cookie、完整分享文本或媒体内容。当前尚未配置集中式日志、追踪、指标或告警；不要求引入未使用的观测平台。

## 故障处理

外部平台不可达、链接失效、媒体格式不支持、存储异常或转换失败时，页面给出可理解的错误并回收输入。接收中断、取消和任务超时均释放繁忙槽。启动前运行 `make runtime-check`，确认 FFmpeg/FFprobe 真正可执行且有MP3编码器；缺工具不接受新任务。真实平台、真机及容器证据不能由替身测试替代。
