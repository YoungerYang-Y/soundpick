# 生产额度与请求防护

**状态：verified**（本地实现及回归已核对；不表示已部署）
**范围：**0.1.0 单实例部署

## 背景

全站成功额度与接口限频需要在正常运行时跨进程重启保留，同时继续使用单实例、单进程、单活动任务和内存任务。Redis 为可选持久存储；Redis 故障时服务自动降级到有界进程内保护。媒体文件仍是临时数据，不建立媒体历史或个人账户。

## 决策

| 领域 | 约束 |
| --- | --- |
| 配置 | `REDIS_URL` 默认空；空值使用纯内存。`REDIS_KEY_PREFIX` 默认 `soundpick:{protection}`。`REDIS_TIMEOUT_SECONDS=0.1` 同时约束连接与套接字调用，Redis client 不自动重试。`REDIS_RETRY_SECONDS=30` 控制故障熔断后的恢复探测。 |
| 额度账本 | Redis 保存北京时区每日成功额度 ID 与 pending；全站每天最多10首。pending 跨日继续占额，成功归完成日；失败、取消、预约超时及进程重启中断释放预约。 |
| 频率账本 | 各接口 IP 与全站窗口及限额沿用 [生产防刷 Spec](../active/0.1.0/production-protection/spec.md)。失败请求仍计频，检查在请求体读取前执行；直接上传同时计提取与上传。 |
| 故障降级 | Redis 未配置或故障时使用进程内状态，限频最多4096个桶，额度记录另设4096条上限；不淘汰已有 key，容量耗尽时拒绝无法跟踪的新 key。进程继续服务；Redis 故障不会导致停服。 |
| 切换 shadow | 保留本进程已知成功额度、pending 和尚未过期的 rate shadow，切换不清零。故障期间 rate 不回灌 Redis；恢复后内存窗口继续参与限频，直至自然过期。 |
| 恢复 | 每次额度操作及 Redis 恢复时用 Lua 原子合并本进程已知的成功任务 ID 与当前 pending。若合并后额度已超限，则阻止新任务直至额度恢复。 |
| 持久化与重启 | Redis 正常时跨重启持久性依赖部署者配置 AOF/RDB。故障期间额度为软保护；若进程此时重启，可能丢失内存额度并超过每日10首，恢复合并后再阻止新任务。内存模式重启会清空额度和限频。 |
| 数据迁移 | 不迁移、不自动删除可能存在的旧 `DATA_DIR/.soundpick-protection.sqlite3` 文件。 |
| Redis 命名空间 | 共享 Redis 的不同部署须使用独立 prefix；同一 prefix 不得运行多个应用实例。单实例目录进程锁约束保持。 |
| IP 身份 | 使用 ASGI client 地址与 HMAC 派生限频身份；不持久化明文 IP。默认容器关闭代理头解析，此时代理后请求按代理 peer 地址聚合。 |

## 请求体与代理边界

- 普通请求体默认16KiB；原始上传默认200MiB，并按实际流字节计数。
- 普通请求体接收总超时由 `REQUEST_BODY_TIMEOUT_SECONDS` 配置，默认15秒、范围1–60秒；既有上传和任务超时保持。
- 请求体声明大小先于读取校验，上传实际字节受 `MAX_MEDIA_BYTES` 限制；上传超限在读取视频块前拒绝。
- 任务、上传和交付继续绑定创建会话；越权访问返回404，不泄露任务是否存在。
- 容器默认关闭 Uvicorn 代理头解析。可信代理部署需显式配置精确 peer IP/CIDR、限制源站直连，并确保代理覆盖客户端 `X-Forwarded-For`；不得使用 `*`。

## 限额

每次匹配请求原子检查并消耗其列出的 IP 与全站预算。检查在读取请求体前执行；认证失败、输入错误、CSRF 失败及其他失败请求仍计频。

| 请求组 | IP 限额 | 全站限额 |
| --- | --- | --- |
| 登录 | 10/分钟，30/15分钟 | 60/分钟，300/15分钟 |
| 提取 | 6/分钟 | 20/分钟，30/小时 |
| 上传 | 6/分钟 | 20/分钟 |
| 轮询、能力查询、取消 | 120/分钟 | 600/分钟 |
| 下载（含 HEAD、Range） | 30/分钟 | 120/分钟 |

超限返回429和 `Retry-After`；JSON 响应提供相同秒数的 `retry_after` 字段。

## 验收边界

本地270项严格回归通过，含真实临时 Redis 的断连恢复、丢响应、quota key 丢失、原子额度和 Lua 限频拒绝；独立代码审查已完成。详细结果见 [实施计划](../active/0.1.0/production-protection/plan.md#validation-record)。未连接用户生产 Redis、未核验其 AOF/RDB，也未部署或重验容器。
