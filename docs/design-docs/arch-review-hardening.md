# 任务确认、媒体有效性与可测试性

## Context

整仓审查发现：

- 上传接收完成到 202 送达之间，没有可恢复的任务标识。
- 重复取消能打断子进程回收。
- MP4 元数据不保证画面可解码。
- 平台注册、交付格式与浏览器共享状态增加了扩展和回归成本。

本决策保留单进程、单活动任务和临时存储约束。

## Decision

### 创建确认与取消

浏览器使用 `crypto.getRandomValues` 生成 32 位小写十六进制任务 ID。

| 文件输入步骤 | 接口与输入 | 返回 |
|--------------|------------|------|
| 1. 预约 | `POST /api/tasks/reservations`，JSON `{task_id,filename?}` | 202 TaskView |
| 2. 确认预约后上传 | `POST /api/tasks/{id}/upload`，原始视频流 | 202 TaskView |

- 两步均校验认证和 CSRF；流式入口按实际字节限制。
- 不使用客户端文件名拼接存储路径。

预约与上传约束：

- 同 owner、同 ID、同输入类型的预约重放返回已有任务；其他 owner 返回 404。
- 任务 ID 绑定创建时的输入类型；跨上传/分享类型重放返回 409，分享任务不接收上传流。
- 重复上传或终态上传返回 409，不覆盖输入、不重启处理。
- 预约占用单活动槽；未开始接收的预约在上传时限到期后失败并清理。
- 入口校验和周期清理均执行预约过期规则。
- 结果保留规则沿用全部终态的 TTL 和容量上限。

分享输入约束：

- 仍使用 `POST /api/tasks/link`，可携带同样的 `task_id`。
- 仅同 owner、同 ID、同规范化链接的重放返回已有任务，且不重复启动。
- 链接绑定只保留进程内 SHA-256 指纹，不向 TaskView 公开、不保存原链接。
- 规范化主机名和默认端口，移除 fragment，保留 path 和 query。
- 换链接需新 ID，即使不同链接实际指向同一视频。
- 无客户端 ID 的旧创建接口继续兼容；网页改用可恢复协议。

响应丢失与状态优先级：

- 预约、创建或上传响应丢失时，网页保留 ID，通过原任务查询/取消恢复。
- 未知 ID 的 404 不代表尚在途的创建已经停止；网页保持未确认状态，创建响应到达后补发取消。
- 仅收到服务端终态确认后恢复创建新任务操作；不重传不确定的上传。
- 查询成功后以查询状态为准；迟到的创建成功或错误响应不得覆盖视图、回退上传进度或清空已准备的分享文件。
- 创建成功仍确认任务存在，并处理待补发的取消。
- 查询得到预约状态时，只启动一次尚未开始的上传。

取消与回收：

- 同一任务的取消请求共享一个取消操作；等待者断开不取消清理。
- 媒体子进程创建和回收在独立受保护任务中完成。
- 即使再次注入取消，也先回收，再传播取消异常。

### 媒体有效性与交付

- 同一任务成功后保留 MP3 与可用 MP4。
- 实际 MP4 保留原字节；其他容器仅无损封装，不额外下载或重编码。
- MP4 准备失败不抹去已成功的 MP3。
- 两种结果共享 owner、保留截止时间、容量与发送引用。
- 到期拒绝新响应，最后一个发送结束后回收整个目录。
- 失败、取消、整体超时、关闭和重启的清理覆盖两种文件。
- 具体接口与验收见 [MP4 设计](../active/0.1.0/video-download/design.md)。

媒体有效性：

- 视频必须至少含一条非 `attached_pic` 画面流及声音轨道。
- MP3 仍从第一完整音轨生成。
- 准备 MP4 时，在处理超时内对实际 MP4 或无损封装结果的画面执行完整解码至 null；该检查不改变交付字节。
- 损坏画面导致 MP4 单独降级，有效 MP3 仍可下载。
- 取消和整体超时仍删除全部媒体。

交付契约与生命周期：

- `app/services/artifacts.py` 集中定义两种格式的固定存储名、MIME、后缀和附件策略。
- TaskView 兼容现有字段。
- 文件引用覆盖响应构造和实际发送；构造失败也归还引用。
- 关闭时立即使任务过期，保留仍在交付的引用；最后一次交付结束后删除文件和任务记录。
- 外部元数据规范化未配对 Unicode 代理字符，保留合法 emoji。

### 平台与浏览器封装

- `PlatformSpec` 唯一登记平台 ID、名称、允许域名、解析器工厂和配置字段。
- URL 识别、工厂装配、能力列表及任务解析共享同一 catalog。
- 真实第三 Adapter 测试验证完整路由。
- 上游 JSON 集合字段校验后才迭代；畸形结构进入备用解析路径，精确原视频 ID 约束保持。

前端使用原生 ES 模块，不增加构建步骤：

| 模块 | 职责 |
|------|------|
| `app.js` | 任务与请求生命周期 |
| `task-view.js` | 呈现 |
| `file-share.js` | 有界 MP3 缓存和系统分享 |

- 页面暂停使旧请求失效；恢复后仅当前请求更新视图。

### 诊断与测试

- 记录任务 ID、阶段和受控错误类别。
- 不记录异常原文、完整分享链接、标题、Cookie、密码或媒体内容。
- 公开错误继续使用固定可读文案。

| 命令 | 检查范围与边界 |
|------|----------------|
| `make test` | 加载媒体工具配置并要求真实工具；缺工具明确失败 |
| 直接 pytest | 仍可用于局部测试，明确报告跳过 |
| `make coverage` | 使用 coverage.py 测量应用 Python 语句及分支，综合覆盖门槛 85%；混合单测/集成测试，不包括 JS 及媒体子进程内部 |
| `make ui-check` | 模块语法和可控时序回归 |
| `make browser-check` | 使用可配置 Playwright/Chromium，启动独立回环 HTTP 服务和临时数据 |

`make browser-check` 的验证与清理约束：

- 验证真实上传、MP3 试听加载、MP4 原字节下载及 202 延迟送达时的取消。
- 默认重复 5 轮；退出回收浏览器、服务和临时数据。
- 不代表 iPhone/Android 或系统分享验收。

## Consequences

- 文件输入增加一次小 JSON 预约请求，换取响应丢失后的可恢复取消。
- 完整画面校验增加 CPU 与时间，仍受现有处理上限约束。
- 无数据库、队列、历史记录、前端框架或动态插件加载。
- 手机、实网平台和容器验收单独记录。
