# 运行能力、网络回退与当前任务恢复

## Context

系统性优化发现三个实际问题：媒体工具存在并不代表能运行或编码 MP3；固定 DNS 首地址不可达会使平台请求直接失败，同 IP 的跨域跳转还会复用以 IP 为归属的 Cookie；刷新页面会丢失仍在服务器处理的任务入口。保留单进程、单活动任务、共享密码、无历史记录和临时媒体的产品约束。

## Decision

Web lifespan 在开放服务前执行媒体工具的异步运行检查，验证 FFmpeg/FFprobe 版本输出和精确的 `libmp3lame` 编码器。检查总超时 10 秒、每条命令输出限制 64 KiB，复用媒体子进程的取消与回收。检查失败仍可启动 Web，但能力接口返回不可用，新任务返回 503。能力请求读取缓存，不重复启动子进程；配置或工具变化后重启服务重新检查。CLI `make runtime-check` 使用同一检查逻辑。

网络请求先验证全部 DNS 地址为公网地址，仅在建立连接发生 `ConnectError` 或 `ConnectTimeout` 时依序尝试其他地址。HTTP 错误响应、读写错误和已开始的媒体流不重放。每次重定向使用独立 HTTP 客户端，隔离 Cookie 与连接池；保留原域 Host/SNI、逐跳地址校验、超时、容量和跳转次数限制。TLS 跨域误复用在旧实现默认 HTTP/1.1 下未复现，不作为已确认缺陷；同 IP 跨域 Cookie 泄露已由失败回归确认。

浏览器仅在 `sessionStorage` 保存一个当前任务的随机 ID、创建确认标记和取消意图。刷新后锁定创建入口，查询服务器状态后呈现任务或结果，不保存分享文字、文件、标题或媒体，也不重新发送上传。已确认任务的 404 清除记录；尚未确认创建的 404 保留重连与取消入口，不能将尚在途的创建宣称为已停止。恢复时认证失效清除记录并提示重新登录；取消意图在查询确认任务后继续提交。重置、过期清除记录，浏览器禁止存储时降级为当前页面流程。

## Consequences

启动新增一次有界工具检查；工具失效需重启后重新判断。网络回退可能延长连接等待，但仍受单次连接和整体任务超时约束；不保留上游响应 Cookie，解析器不依赖上游 Cookie 会话。标签页恢复提升刷新后的可用性，不提供持久化历史、不恢复服务器重启前的任务，不恢复上传字节。关闭标签页和更换登录会话后不保证入口保留。

## Verification

对应检查包括媒体启动不可用/503、编码器精确匹配、超时与进程回收；DNS 回退、不重放响应或流、私网混入拒绝与 Cookie 隔离；浏览器处理中/完成状态恢复、取消意图、过期、认证和存储降级。实际运行结果见[本轮验证记录](../references/system-optimization-verification.md)。
