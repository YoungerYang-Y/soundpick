# 已确认需求

本文记录产品范围和明确的用户约束。没有写在“已确认”中的实现选项均不视为用户承诺。

## 用户与目标

- 使用者是项目所有者本人及家人。
- 提供一个手机优先的网页，帮助用户取得短视频的完整原音轨 MP3，并可下载完整原视频 MP4。
- 桌面浏览器也应能访问。

取舍顺序：

1. 原音轨正确性与数据安全。
2. 单次处理可靠性。
3. 手机核心流程。
4. 视觉与交互。

- 操作保持简单；无法确认原音轨时明确失败。
- 系统分享不承诺特定目标或保存目录。

## 输入与来源

- 首期来源为抖音和火山，后续平台应可扩展。
- 用户可以粘贴单个分享链接，也可以粘贴包含分享信息的整段文字。
- 用户也可以上传本地视频文件。
- 每次处理一个视频。

## 输出与操作

- 输出必须是视频的完整原音轨，格式为 MP3。
- 不做 AI 去人声、不裁剪、不批量处理。
- 提取完成后可试听并下载。
- 同一次处理还应提供完整原视频的 MP4 下载，覆盖分享链接和本地上传；保留原画面和声音，不裁剪。
- 浏览器支持时提供系统分享或保存文件的体验；实际分享目标和保存位置受浏览器、操作系统与用户选择影响。

## 账户、历史与临时数据

- 使用共享密码保护页面，不建立个人账号。
- 不保留用户历史记录。
- 上传内容、下载媒体和处理产物均为临时数据，自动清理。
- 成功后只保留交付用的 MP3 与 MP4；失败或取消删除全部文件。
- 结果在保留期内供下载，到期删除。
- 不保留媒体处理历史；用于保护功能的状态数据不包含媒体内容或分享文本。

## 生产额度与请求防护

- 全站按北京时区每天最多成功处理 10 首；MP3 与同任务 MP4 合计一首。
- 未完成预约跨日仍占用当日可用额度；成功计入完成日。失败、取消、预约超时及进程重启中断释放预约。
- 可选 Redis 是保护状态的持久存储；正常连接且 Redis 配置 AOF/RDB 持久化时，额度和限频跨重启保留。`REDIS_URL` 留空时使用进程内保护。Redis 故障时自动降级，服务继续运行；故障期额度为软保护，重启可能丢失内存状态并超过每日 10 首。单实例、单进程约束继续成立，同一 Redis 中每个部署使用独立 `REDIS_KEY_PREFIX`，同一 prefix 不得由多个应用实例共享。
- Redis 恢复时以 Lua 原子合并进程已知的成功任务 ID 与当前 pending 预约；若合并后超过每日额度，则拒绝新任务直至额度恢复。故障期的限频事件不回灌 Redis，但进程内窗口持续限制请求。内存限频最多 4096 个桶，额度记录另设 4096 条上限，不淘汰 key 来绕过限额；达到上限时拒绝无法跟踪的新 key。
- Redis AOF/RDB 持久化由部署者负责。旧 SQLite 文件不迁移，也不会自动删除。
- 接口限额及代理信任部署边界见[生产额度与请求防护决策](./design-docs/arch-production-protection.md)。

## 已知边界与待确认

### MP4 下载

- 新增于 2026-10-03，设计与验收见 [原视频下载](./active/0.1.0/video-download/spec.md)。
- 优先保留已有 MP4 的原始字节；其他容器尝试无损重新封装，不重新压缩画面或声音。
- 无法无损封装时单独提示 MP4 不可用；已成功的 MP3 仍可试听下载。
- 不承诺改变源编码以适配所有手机播放器。

### 工程指标与平台验证

- 用户尚未设定上传大小、视频时长及文件保留期的产品硬性指标；MVP 使用可配置工程默认值：200 MiB、30 分钟、结果保留 1 小时，见 [MVP 规格](./active/0.1.0/audio-extraction/spec.md)。
- 30 秒不是硬性要求。
- 抖音和当前火山版各已验证一个精确目标的实网解析、视频下载及完整 MP3 转码样本。
- 火山版当前样本使用共用抖音域短链；旧火山域样本仍未恢复。
- 解析与来源边界见 [平台解析记录](./references/platform-parsing.md)；单个成功样本或已配置路径不代表全部链接已可用。

### 来源与处理边界

- 分享内容只有在用户主动发起请求后才处理；不提供后台批量抓取。
- 分享链接可能返回背景音乐或其他素材，不能把它们冒充原视频原音轨。原音轨来源及验证策略仍需按平台能力确认。
